5. Basis of preparation and limitations

  • Point in time. Holdings are stated as of {{ r.period.end.time_utc | utc }} (block {{ r.period.end.height }}); nothing here says what the wallet holds after that.
  • Control, not title. A proof shows that the keys behind an address signed the message. It does not show who owns the coins, whether they are pledged, lent or otherwise encumbered, or what liabilities stand against them.
  • Completeness. The movements and holdings are those of this wallet as known to the holder's node. That the wallet is the holder's only one, or that all of its addresses are in the node, rests on the holder's representation; no cryptographic check establishes it.
  • Scripts, addresses and UTXOs. BIP-322 defines a proof for a scriptPubKey, "the key script to be proven"; an address is that script, checksummed and encoded, and the proof is not about any particular coin. Coins are UTXOs, each locked to exactly one scriptPubKey, which the node reports. Each page of section 4 reads the UTXO's scriptPubKey from the chain and runs the verifier on those same bytes; control of the script is therefore control of the UTXO. A script proven once is covered for every UTXO paid to it, before or after the proof; the date of each proof is the block named in its message.
  • No wallet structure is disclosed. The statement and the bundles name addresses and outputs only; they carry no descriptor, extended public key or derivation path.

6. Verification procedures

Every figure and proof above is checkable on any Bitcoin node with the chain, without a wallet or an index.

  1. Proof of control, per UTXO. Run the verify command printed on the UTXO's page in section 4; its first argument is the scriptPubKey, the same bytes the lookup below it reports for the UTXO; it prints what is printed here, starting with VALID. Paste it as it stands: the backslashes continue the command across lines, and the message keeps its own line break inside the quotes. For a second opinion, bip322-refcheck ADDRESS PROOF MESSAGE runs independent implementations beside it, and bitcoin-cli getblockheader HASH with the hash from the message's last line confirms the block's height and time.
  2. Holdings, per UTXO. Run the lookup command printed on the UTXO's page (a direct lookup, instant); its --at is the block named in the proof's message, so control and holding are checked at one block. Its "locked to" line is the scriptPubKey the proof is verified against; the address beneath it is the same bytes encoded, and bip322 validateaddress or bitcoin-cli validateaddress converts between the two. To look inside a proof, bip322 decodesignature PROOF --text shows the witness script it carries and derives the scriptPubKey from it. An output spent after the period's end no longer shows; report.json names the transaction that spent it. The same by address, bip322 audit holdings ADDRESS --at BLOCK, scans the whole UTXO set and takes minutes on a mainnet node.
  3. Movements. Each transaction in section 2 by txid; the running balance follows from the opening balance and the net of each.
  4. All of it at once. The proofs come as files next to this statement{% if r.bundles %}: {% for b in r.bundles %}ledger/{{ b.bundle }}{% if not loop.last %}, {% endif %}{% endfor %}{% endif %}. bip322-audit verify FILE checks every proof in a file, its stamp block, and that every output the file lists existed at that block. report.json carries every figure of this statement and its reference {{ r.report_id }}. Both tools install with pip install bip322-reports.
